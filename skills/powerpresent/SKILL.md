# PowerPresent

把一堆材料（论文、代码仓库、产品文档、旧 PPT）做成一份外行也能一遍读懂、观感专业、可在 PowerPoint 里直接编辑的演示文稿。

## 先读这四份指南

| 文件 | 管什么 | 什么时候读 |
|---|---|---|
| `references/narrative.md` | 故事线：听众、主旨、章节骨架、开场与结尾 | 第 1、2 步之前 |
| `references/copywriting.md` | 文字：结论式标题、术语取舍、每页字数、中英混排 | 第 2、3 步之前 |
| `references/design-system.md` | 视觉：配色、字体、版面、图示画法、禁止事项 | 第 3、4 步之前 |
| `references/components.md` | 组件：怎么调用、什么内容用哪个组件 | 第 4 步之前 |

四份都要读完再动手。指南里的规则是硬性要求，不是建议。

## 工作流

### 第 1 步：问清五件事，定下四个选项

向用户确认（材料里已有答案的不必再问）：听众是谁、他们已经知道什么、听完要记住哪一句话、希望他们做什么、讲多久。然后定下：

| 选项 | 取值 | 怎么定 |
|---|---|---|
| 配色 `palette` | `journal` / `ink` | 学术场景用 `journal`，商业场景用 `ink` |
| 底色 `surface` | `light` / `dark` | 会被传阅、截图多、明亮会议室用浅色；暗场大屏用深色；拿不准选浅色 |
| 密度 `density` | `read` / `talk` | 页面要能脱离演讲者被读懂用 `read`；有人现场讲解用 `talk` |
| 底图 `backdrop` | `wafer` 等六种 | 默认芯片版图；按题材选，见 `design-system.md` 第 9 节 |
| 页数 | 约等于分钟数 | 每页讲 1～2 分钟；细节放附录 |

### 第 2 步：写主旨句和标题提纲，交用户确认

1. 用一句话写出全篇主旨。写不出来就回到材料，不要往下做。
2. 分 3～5 章，章节名每个不超过 6 个汉字。
3. 写出每一页的标题。**每个标题是一句完整的结论，且能放进一行。**
4. 只读标题串一遍：能连成一段完整的论证才算过关。
5. 把主旨句和标题提纲发给用户确认，再进入下一步。

### 第 3 步：给每一页配证据，选好组件

对每一页回答两个问题：这页的结论靠什么证明？用哪种形式呈现？

- **先想图，再想字。** 内容里有“包括、分为、调用、流向、依赖、反馈”这类关系的，画成图示；结果和产品用真实截图、实拍、数据图。技术稿里图示页与图片页应占内容页一半以上。
- 按 `references/components.md` 第 7 节和 `references/design-system.md` 第 10.1 节选组件。
- 列出需要的真实素材（截图、照片、数据、图表数值），向用户索取或从材料里提取。**不得编造数据，不得用生成的图片冒充真实截图或实验图。**
- 数字写清单位、对比基准和来源。

### 第 4 步：写构建脚本

每份稿子一个目录：`build.py`、`assets/`（真实素材）、`out/`（产物）。脚本骨架：

```python
import sys
sys.path.insert(0, "<skill 目录>/scripts")
from powerpresent import Kit

kit = Kit(palette="journal", surface="light", density="read", footer="稿名 · 日期", sections=["问题", "方法", "结果", "结论"])
kit.cover("主标题", subtitle="副标题", kicker="场合", meta=["汇报人", "单位 · 日期"])
page = kit.content("一句结论式标题", section=0)
area = page.takeaway("这一页最想让人记住的一句话")
# ……用 area.cols() / rows() 切分版面，放入组件……
kit.closing("收束全篇的一句话", points=["结论一", "结论二"])
kit.save("out/deck.pptx")
```

- 只用组件库和主题里的取值，不写十六进制色值，不手算坐标，不指定字体。
- 完整示例见本仓库 `examples/demo/build.py`（完全虚构的《云杉计划》）；把本 skill 单独复制到其他项目时，按上面的骨架起步，不依赖这个示例。

### 第 5 步：渲染，逐页看图，改到没有问题

```bash
python build.py                                              # 保存时会打印“需要修改”的问题，必须全部改掉
python <skill 目录>/scripts/render_pptx.py out/deck.pptx out/preview
```

**逐页打开预览图看**，不要只看脚本有没有报错。常见问题与处理顺序：

| 现象 | 处理 |
|---|---|
| 文字溢出容器、折成意外的两行 | 先删字，再减条目，再换组件，最后拆页。不缩字号 |
| 卡片里大片空白 | 把卡片改矮（先用 `rows` 切出合适高度），或换成横排、纵排 |
| 连线穿过别的框或压到文字 | 调整格子的划分与间距，不要硬连 |
| 整页只有文字、没有明暗层次 | 加带标题头带的卡片、数据块或结论条（`design-system.md` 第 2.5 节） |
| 满页都是实心色块，显得沉重 | 实心块一页两三处即可；把示意图和图表放进 `page.panel`，其余用白卡片 |
| 原材料里有图表或示意图 | 照原图的结构重画成可编辑的形状，不要降级成几行文字或几个数字 |
| 页标题超过一行 | 改写标题 |
| 页面上小字、标签、提示语很多 | 逐个遮住看：少的是“关于页面的指引”就删，并改布局；少的是“关于内容的信息”就留 |

改完重新渲染再看，直到每一页都过关。

### 第 6 步：三份清单逐条自查

- `references/narrative.md` 末尾的叙事自查清单
- `references/copywriting.md` 末尾的文案自查清单
- `references/design-system.md` 第 13 节的视觉自查清单

### 第 7 步：交付

交付 `out/deck.pptx` 和预览图，并如实告诉用户：

- 预览图由 LibreOffice 渲染，字间距和阴影与 PowerPoint、WPS 略有出入，请在目标软件里再看一遍。
- 字体用的是黑体、宋体、Times New Roman，没有这些字体的电脑上会被替换。
- 哪些页面用了占位内容或尚缺真实素材。

## 不可违反的规则

1. 页标题是一句完整的结论，占一行。
2. 页面干净、直接：删掉次要文字（重复信息、读图提示、装饰性标签），保留有实质内容的解释；一页非得靠读图提示才看得懂，就改布局。
3. 一份稿子只用一套配色、一种底色、一档密度。
4. 西文与数字用 Times New Roman；汉字大标题用不加粗的黑体，其余用加粗的宋体。
5. 复杂内容画成图；2D 图示纯色加描边、不加阴影和光效，2.5D 图示半透明、加阴影和柔光、不描边。
6. 不使用发光、渐变文字、粒子或光斑背景、玻璃卡片等“AI 生成感”做法；底图只用低对比度的纹理。
7. 数据、截图、引文必须真实，有来源。
8. 文字、形状、图表保持可编辑，不把内容做成图片。

## 环境

Python 3.11 以上，依赖 `python-pptx` 与 `Pillow`；渲染预览需要本机安装 LibreOffice（`soffice`）和 poppler（`pdftoppm`）。`scripts/generate_image.py`（封面气氛图）另需 `google-genai` 与已登录的 `gcloud`，属于可选功能。
