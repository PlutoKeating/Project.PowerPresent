# 设计系统指南

这份指南管页面长什么样：配色、字体、字号、版面、页面框架、光效与形状。文字怎么写见 `copywriting.md`，故事怎么排见 `narrative.md`，组件怎么调用见 `components.md`。

所有取值都实现在 `scripts/powerpresent/theme.py`，组件只从那里取值。**不要在页面代码里写死颜色和字号**；要调整视觉，改 `theme.py` 一处。

## 1. 六条总原则

1. **一页一个视觉重点。** 读者的视线只应被拉向一个地方：最大的数字、实心的卡片、或底部的结论条，三者只选其一。
2. **对齐和留白优先于装饰。** 先用网格把东西摆整齐、把间距留够，再考虑光效。页面显得乱，几乎都是对齐和间距的问题。
3. **克制。** 颜色只承担功能（层级、角色、强调），不做装饰；页面框架不用发光和渐变文字；底图只用低对比度的纹理。
4. **一致性大于单页的漂亮。** 同一类内容在全稿里永远用同一种组件、同一个位置、同一个颜色。
5. **干净、直接。** 每页一个明确的视觉落点和一条凭直觉就能走的阅读路径。砍掉不必要的次要文字（重复信息、读图提示、装饰性标签），保留有实质内容的解释；一页如果非得靠读图提示才看得懂，就去改布局（见 `copywriting.md` 第 1.1 节）。
6. **复杂内容画成图，证据用真图。** 架构、链路、机制、组成这类内容，用框线图和分层图表达，不写成要点列表；结果和产品用真实截图、实拍和数据图证明，不用装饰插画。详见第 10 节。

## 2. 配色

### 2.1 两套配色，按场景选一套

| 配色 | 名称 | 气质 | 首选场景 |
|---|---|---|---|
| `journal` | 期刊蓝与赭黄 | 严谨、像期刊 | **学术**：会议报告、研究汇报、答辩 |
| `ink` | 墨与朱 | 克制、黑白灰加一个朱色，编辑感 | **商业**：产品发布、路演、企业介绍 |

一份稿子只用一套配色、一种底色。不得自创第三套，也不得往一套里加别的色相。

### 2.2 颜色从哪里来

配色不凭感觉挑，按三条规则生成（实现在 `theme.py` 与 `color.py`）：

1. **基准色取自公开发表的色盲友好色卡。** `journal` 的主色、强调色、第三色是 Paul Tol 的 high-contrast 三色，图示色相与图表系列是 Tol bright；`ink` 的强调色、图示色相与图表系列来自 Okabe-Ito。
2. **其余颜色在 OKLCH 空间里派生。** OKLCH 是感知均匀的色彩空间：明度 L 相同的颜色看起来一样亮，彩度 C 相同的看起来一样鲜艳。同一组标签固定 L 与 C、只换色相 H，所以并排时天然整齐；色阶是同一色相上等距的明度阶梯。
3. **中性色成体系，深色底单独取值。** 纸、面、线、墨是一组中性色，`journal` 带极低的冷偏（与主色同色相），`ink` 是纯灰。深色底不是把浅色底反色，而是另取一组明度。

### 2.3 基准色

| | `journal` 浅 | `journal` 深 | `ink` 浅 | `ink` 深 |
|---|---|---|---|---|
| 纸（背景） | `#F5F7F9` | `#0E141D` | `#F7F7F7` | `#0F0F0F` |
| 面（淡底卡片） | `#EAEDF1` | `#171F28` | `#EBEBEB` | `#1B1B1B` |
| 线（分隔、卡片边） | `#D0D5D9` | `#2F3640` | `#D1D1D1` | `#333333` |
| 墨（正文） | `#171D26` | `#FFFFFF` | `#161616` | `#FFFFFF` |
| 次要文字 | `#636A71` | `#DDE2E8` | `#636363` | `#E0E0E0` |
| 主色（标题、实心块、结构标记） | `#004488` | `#71A8E8` | `#161616` | `#E8E8E8` |
| 强调色（小面积图形、色条） | `#DDAA33` | `#E5B650` | `#D55E00` | `#F27636` |
| 强调文字（正文里要紧的字） | `#BB5566` | `#E5B650` | `#B14A00` | `#F27636` |

- 图表系列色：`journal` 用 Tol bright（`#4477AA #EE6677 #228833 #CCBB44 #66CCEE #AA3377`），`ink` 用 Okabe-Ito（`#0072B2 #D55E00 #009E73 #E69F00 #56B4E9 #CC79A7`），按顺序取用。
- `ink` 没有彩色主色：标题、实心块都是墨色，全稿唯一的彩色是朱色强调。这正是它的气质所在，不要给它补一个“品牌蓝”。

### 2.4 两种强调，分工明确

| 强调类型 | 取值 | 用在哪里 |
|---|---|---|
| 结构强调 | 主色（`theme.accent`） | 章节标记、卡片小标题、序号、箭头、要点符号。告诉读者“页面是怎么组织的” |
| 内容强调 | 强调文字色（`theme.highlight`） | 正文里最要紧的几个字。告诉读者“记住这个” |
| 图形点睛 | 强调色（`theme.mark`） | 封面色条、署名分隔线、深色底的大数字。只用于小面积图形，不用于正文文字 |

- 内容强调每页**最多三处**，写法是在文字里用 `**双星号**` 包住。超过三处等于没有强调。
- 正文本身已经是粗体，所以强调只靠颜色，不要再用下划线、斜体或加大字号。
- 强调色的面积要小，具体比例见第 2.5 节。

### 2.5 明暗层次与撞色点缀

一页上如果只有“背景色加文字”，就会整页一个亮度、文字糊成一片；反过来，实心色块用得太多，页面又会沉重、刺眼。每个内容页由下面四层组成：

| 层 | 是什么 | 由谁提供 |
|---|---|---|
| 底 | 页面背景和普通卡片（卡片要比背景明显亮一档） | 背景、`card` |
| 色调带 | 主色的浅色调（深色底上是较亮的色调），用来给内容分区 | 卡片的标题头带 |
| 反色块 | 与背景明暗相反的实心色块：浅色底上是深色块，深色底上是较亮的色块 | 表头、列标题、结论条、页脚带、图示的分组头带与层名块、重点卡片与重点数据块 |
| 撞色点 | 小面积的强调色（赭黄或朱色） | 序号圆点、要点符号、箭头、页码块、页眉短色段、时间标签、标注点 |

- **反色块用来分隔内容。** 两段文字之间要么隔着一条头带，要么各在一张卡片里，不能只靠空行。
- **实心反色块要省着用**：除页脚带外，一页两到三处，合计不超过页面面积的两成。卡片的标题头带用浅色调而不是实心色，数据块默认是白卡片；只有全页最要紧的那一张卡片或那一个数字才用实心（`tone="strong"`）。
- **示意图和图表放在图示面板上**（`page.panel`）：一块带柔和投影的圆角浅色底，把图从背景里托出来。
- **撞色点每页至少三处、合计不超过页面面积的 5%**，并且都落在有功能的位置（序号、方向、页码），不做纯装饰。
- `journal` 深色底的反色块用中等明度的蓝 `#1F5FA8`；`ink` 深色底的反色块是近白色，所以每页都出现的页脚带改用深灰，避免每页底部一道白。
- 封面、章节页、结尾页各有一块大面积的反色块，是全稿明暗对比最强的地方。

### 2.6 图示标签的取值规则

2D 图示里的彩色标签（节点、分组）按固定的明度与彩度生成，只换色相：

| | 填充 (L, C) | 描边 | 文字 |
|---|---|---|---|
| 浅色底 | 0.955, 0.028 | 0.74, 0.085 | 0.42, 0.10 |
| 深色底 | 0.40, 0.085 | 0.66, 0.12 | 0.92, 0.075 |

**深色底的两条特别规定**：其一，凡不是强调色的文字（正文、说明、节点里的副文字、图注）一律用亮白或接近亮白，不用中灰，否则整页发暗；其二，彩色卡片的填充要足够亮（明度 0.40 左右），不能只比背景亮一点点。

这样得到的标签是“浅底、同色系的描边和文字”：颜色有区分度，但明度对比低，不刺眼。新增色相时沿用这组 L 与 C，不要单独调某一个颜色。

### 2.7 对比度

正文、次要文字、强调文字对背景的对比度均不低于 4.5:1。`ink` 的朱色 `#D55E00` 在浅纸面上只有约 3.6:1，所以它只做图形，文字用加深的 `#B14A00`。新增文字颜色组合前用 `color.contrast()` 核算。

## 3. 两种底色怎么选

每套配色都有浅色底与深色底，一份稿子只选一种，不混用。

| | 浅色底 `light` | 深色底 `dark` |
|---|---|---|
| 适合 | 会被打印、传阅、细读的材料；截图和数据图多的稿子；明亮的会议室 | 暗场、大屏、舞台演讲 |
| 背景 | 接近白的纸色 | 接近黑的深色，不是纯黑 |
| 卡片 | 比纸面略亮，细线描边，极淡的投影 | 比背景略亮的面色，细线描边 |
| 截图多时 | 首选 | 截图多为白底，放上去会很跳，慎用 |

拿不准时选浅色底。常见组合：学术汇报用 `journal` 浅色底；发布会与路演用 `ink` 深色底或浅色底。

## 4. 字体

**硬性规则，全稿无例外：**

| 文字 | 字体 | 字重 |
|---|---|---|
| 西文字母与阿拉伯数字 | Times New Roman | 跟随所在位置 |
| 汉字 · 大标题（封面标题、章节标题、页标题、大数字） | 黑体 | 不加粗 |
| 汉字 · 其余全部（导语、小标题、正文、标签、图注、页脚） | 宋体 | 加粗 |

- 不使用第三种中文字体，不用艺术字、书法字。
- 汉字与西文、数字之间加一个半角空格（写文案时就加好，见 `copywriting.md`）。
- PPTX 不能可靠地内嵌中文字体。黑体、宋体、Times New Roman 在 Windows 上自带；在没有这些字体的电脑上打开会被替换，交付时要提醒。

## 5. 字号与两档密度

开工时先定密度档，全稿统一：

| 角色 | 演讲档 `talk` | 阅读档 `read` | 说明 |
|---|---|---|---|
| 封面标题 | 46 | 44 | 最多两行 |
| 章节标题 | 40 | 38 | |
| 页标题 | 30 | 28 | **只占一行**；放不下就改写标题 |
| 大数字 | 48 | 42 | 数据块 |
| 导语 | 18 | 16.5 | 页标题下面的一行 |
| 卡片小标题 | 21 | 18.5 | |
| 正文 | 18 | 15 | |
| 辅助文字 | 14 | 12.5 | 标签、备注、单元格 |
| 图注与出处 | 12 | 11 | 全稿最小字号 |

- 单位是磅，页面宽 13.33 英寸。任何文字不得小于该档的“图注”字号。
- **放不下时删字或拆页，不要缩字。** 组件不会自动缩小字号。
- 每页字数上限见 `copywriting.md`：演讲档约 80 字，阅读档约 220 字。

## 6. 版面与留白

画布是 1600 × 900 的虚拟像素（16:9）。

| 区域 | 位置 | 内容 |
|---|---|---|
| 页眉带 | y 32～74 | 左：章节标记；右：章节索引 |
| 标题区 | y 94～190 | 页标题一行、导语一行 |
| 内容区 | x 80～1520，y 206～806 | 所有组件都放在这里 |
| 页脚带 | y 838～876 | 左：稿名与日期；右：页码 |

- **左右页边 80，任何内容不得越过。** 内容区是唯一可以摆放组件的地方。
- 模块之间的标准间距是 24；卡片内边距 22。间距只用 24 的倍数或一半（12、24、48）。
- 用 `Rect` 的 `cols` / `rows` / `grid` 切分内容区，不要手算坐标。并排的模块等宽或成简单比例（1:1、2:1、3:2）。
- **容器的高度跟着内容走。** 内容少就让卡片矮一些、把剩余空间留白，或换成更合适的组件；不要为了填满页面把卡片拉高，也不要为了塞进内容把间距压掉。
- 内容区至少留出 15% 的空白。整页被填满时，拆成两页。
- 同一行的模块顶边对齐、底边对齐；跨页的同类模块出现在同一位置。
- 连线和箭头只走模块之间的空隙，不穿过文字，不压在色块上。

## 7. 页面框架

每份稿子由四种页面组成，全部由组件库生成，不要手工拼。

| 页面 | 作用 | 固定元素 |
|---|---|---|
| 封面 `cover` | 说清这是什么、谁讲 | 场合名、主标题（竖条强调）、副标题、署名与日期 |
| 章节页 `section` | 换章时让听众喘口气、知道接下来讲什么 | 大序号、章节名、本章 2～4 个小节 |
| 内容页 `content` | 推进论证 | 页眉、页标题、导语、内容区、页脚 |
| 结尾页 `closing` | 把全篇收束成一句话 | 收束句、最多三条结论、联系方式 |

内容页的页眉和页脚（这是全稿统一感的来源，不得省略或改位置）。导语（`lead`）是可选项，默认不写：

- **章节索引**（右上）：列出全部章节，当前章节实心高亮，其余淡显。听众随时知道讲到哪了。章节数 3～5 个，名字每个不超过 6 个汉字。
- **页标题**：左对齐，占一行。
- **页脚**：通栏的反色带，左侧“稿名 · 日期”，右侧是强调色的页码块。
- **页眉线**：左端有一小段强调色。
- 企业或学校标识放封面右上角；内容页不放，避免每页都抢视线。

## 8. 光效、阴影与形状

页面框架和内容卡片走“平”的路线：

- **标题、正文不加任何效果**：不发光、不投影、不用渐变文字。
- **卡片**：纯色填充，细线描边，一层柔和的投影；带标题的卡片顶部是一条浅色调的标题头带。
- **实心块**（表头、结论条、页脚带、章节索引的当前项、重点卡片）：纯色，不用渐变。
- **渐变只出现在页面背景**：同一色相、明度差约 0.03 的斜向渐变，上面叠一层很淡的底图（第 9 节）。其他地方不用渐变。
- **光效（柔光、半透明、明显的投影）只留给 2.5D 示意图**，见第 10.3 节。
- 圆角统一：卡片用小圆角，标签和索引用全圆角。不混用直角与大圆角。
- 异形只用以下几种，且各有固定含义：

| 形状 | 含义 |
|---|---|
| 箭头形（chevron） | 先后顺序、因果推进 |
| 梯形层叠板、斜视平板 | 分层架构，上层依赖下层（2.5D 画法） |
| 圆形节点 | 流程中的环节 |
| 两端上翘的托线 | 一组无框要点的收边 |
| 全圆角胶囊 | 标签、分类、当前状态 |

不要为了“有设计感”发明新的异形。

### 8.1 必须避开的“AI 生成感”

下面这些是设计社区公认的 AI 默认套路，一出现就让人觉得是机器生成的稿子。本设计系统一律不用：

- 紫到蓝的渐变；近黑底配霓虹青；深色底加发光描边和光晕。
- 渐变文字（标题或指标数字）。
- 粒子网络、光斑色团、流体渐变、发光电路板做背景。（低对比度的磨砂、网格、走线底图按第 9 节使用，不在此列。）
- 到处使用半透明玻璃卡片。
- 卡片或标题左侧的彩色竖条。（卡片顶部的整条标题头带、页眉的短色段不属于此类。）
- 纯黑 `#000000` 或纯白 `#FFFFFF` 做页面背景。
- 没有信息量的装饰性小图表、满屏的图标和表情符号。
- 所有卡片等高等宽、所有元素居中对称。层级应当靠字号、字重和留白拉开，主次元素有意不等大。

## 9. 背景与底图

页面背景由两层组成：一层同色相、明度差很小的斜向渐变，上面叠一张**低对比度、低饱和度的底图**，让画面有不显眼的层次。

### 9.1 可选的底图

底图在 `assets/backdrops/<母题>/`，每个母题都为两套配色、两种底色各备了“内容页”和“封面页”两个强度。用 `Kit(backdrop="母题名")` 选择，全稿统一用一种；`backdrop=None` 表示不用底图。

| 母题 | 画面 | 气质与适用 |
|---|---|---|
| `wafer`（默认） | 芯片版图的块面与细走线，右侧更密 | 半导体与硬件语义最明确；纹理最明显，适合封面与深色底 |
| `brushed` | 横向粗拉丝，明暗对比强 | 金属与制造感；偏硬件、精密制造题材 |
| `blueprint` | 工程制图纸的细网格 | 严谨、工程感；学术与技术汇报 |
| `dots` | 从右下角向左上渐隐的点阵 | 中性、现代；商业与产品介绍 |
| `contour` | 等高线 | 有机、有“测绘”感；封面效果好，内容页很淡 |
| `hairline` | 45° 细斜线与几道宽斜带 | 克制的商务感；黑白灰配色尤其合适 |

### 9.2 底图的规则

- **底图只用配色里的颜色**：纹理的颜色是该配色的主色，按很低的比例混进纸面色。不出现第三种色相。
- **不直接把生成的图片当底图。** 新增底图的做法是：先得到一张灰度纹理（可用 `generate_image.py` 生成，要求平视、均匀光照、没有焦点和文字），再用 `scripts/make_backdrop.py` 加工——去色、只取明暗起伏、低比例叠到纸面色上、内容页加渐隐蒙版、最后加细颗粒。拉丝的粗化与锐化是专用配方：`make_backdrop.py <纹理.png> brushed --recipe brushed --gain 4.2`。
- 不用的题材：发光的写实电路板、蜂窝六边形、数字雨、粒子连线、光斑色团。
- 正文尽量放在卡片或面板里；直接写在底图上的文字，要确认它下面的纹理不影响辨认。
- 封面可以另用一张整幅封面图（`kit.cover(image=...)`）；章节页左侧、结尾页底部各有一块反色色块。

## 10. 复杂内容画成图

工科汇报、科研答辩、产品技术介绍的核心页面，应当是**图**：系统怎么分层、数据怎么流动、机制怎么闭环、方案由哪些部分组成、真实界面和实验结果长什么样。要点列表只适合放结论和解读。

判断方法：如果一页的内容里出现了“包括、分为、调用、流向、依赖、先……再……、反馈”这些关系，就画成图。一份技术稿里，图示页和图片证据页合计应占内容页的一半以上。

### 10.1 选哪种图

| 要表达的内容 | 用哪种图 | 组件 |
|---|---|---|
| 系统分几层，每层做什么、带来什么 | 分层全景图 | `panorama` |
| 底座之上长出平台，平台之上长出应用 | 平台体系图；层数少且想强调承托关系时用 2.5D 层叠 | `tiers` / `iso_stack` |
| 谁调用谁、数据往哪走、边界在哪 | 运行链路图：分组框加节点加连线 | `diagram` |
| 工作分几个阶段，每个阶段内部怎么做 | 分阶段技术路线图 | `stages` |
| 一张大图需要按模块或阶段分区 | 分区泳道 | `lanes` |
| 带反馈、会循环的机制 | 闭环图 | `cycle` |
| 两个主体各做什么、互相给什么 | 双向交互图 | `exchange` |
| 研究现状、方法分类、功能组成 | 分类树 | `tree` |
| 一个核心系统的几个组成或应用方向 | 中心辐射图，配实物照片 | `hub` |
| 改进前后、两种方案的真实界面对照 | 截图对照，中间加结论横条 | `gallery` + `callout` |
| 一张界面或实验图里要看哪几处 | 带标注的截图 | `annotated` |
| 多张实验数据图加结论 | 图文数据页：结论与图用相同编号对应 | `card` + `gallery` |

### 10.2 画图的规则

- **先分区，后放框。** 先用分组框或泳道把图分成 2～4 个区（例如“接入方 / 核心 / 外部”），再往区里放节点。读者先看到结构，再看细节。
- **一张图的节点不超过 15 个**，一个分组内不超过 6 个。超过就拆成“总图加分图”两页：总图只画分组，分图展开其中一组。
- **节点里写名称，必要时加一句不超过 10 个字的职责说明。** 说明要讲“它做什么”，不要重复名称。 解释性的句子放到图外的卡片或讲稿里。
- **颜色代表角色，全稿固定：**

| 色调 | 含义 |
|---|---|
| `plain` 常规 | 一般模块 |
| `primary` 蓝 | 本方 / 主体模块 |
| `solid` 主色实心 | 核心，一张图最多两个 |
| `accent` 绿 | 流程中的动作或可选功能 |
| `warm` 黄 | 数据、存储、产出物 |
| `alert` 红 | 问题、风险、后台或异步环节 |
| `muted` 灰 | 外部系统、次要内容、未启用 |

- **线型代表关系，全稿固定：** 实线是主路径；虚线是异步、可选或事件；双向箭头是互相读写。图例默认不放：分组头带和颜色应当已经让角色一目了然；只有读者确实分不清时才加（`diagram.legend`）。
- **连线要粗到一眼看得见**（默认 2.2，主路径可以到 4），箭头用大号。
- **连线只走横平竖直**，从一个框的边到另一个框的边，走在框与框之间的空隙里，不穿过别的框，不压文字。主流向统一为从左到右或从上到下，全稿一致。
- **线上的标注尽量少。** 只在不标就看不懂的地方写两三个字（如“写回”）。
- **2.5D 只用于层叠关系**（`iso_stack`），最多四层。不要把流程图、拓扑图也做成立体的。
- **图要有结论。** 页标题说出这张图想证明什么；标题已经说清时不再加结论条。只有图、没有判断的页面等于让听众自己做阅读理解。

### 10.3 两套画法，不得混用

示意图只有两套画法。把渐变、半透明、阴影、发光一股脑加在平面框图上，是“一眼看出是 AI 生成的 PPT”的主要来源，必须避免。

| | 2D 示意图 | 2.5D / 3D 示意图 |
|---|---|---|
| 适用 | 框线图、分层全景、平台体系、路线图、泳道、闭环、分类树、中心辐射、步骤流程、分列清单、节点、时间线 | 带透视或纵深的图：梯形层叠板（`stack`）、斜视层叠平板（`iso_stack`） |
| 面 | **纯色**填充，不用渐变和半透明 | 可用**半透明**的面 |
| 标签与节点配色 | **低对比度、高饱和度**：浅底配同色系的描边与文字（深色底上是深底配同色系亮色），取值规则见第 2.6 节 | **柔和的饱和度、高对比度**：近白或深蓝的标签底配反色文字 |
| 阴影 | **不加** | **加**（表现悬浮与层次） |
| 描边 | **加**（1.2～1.5 的细线） | **不加** |
| 光效 | **不加** | **加**柔光 |

- 一张图只用一套画法；同一页上 2D 图和 2.5D 图并排时，各自按各自的画法。
- 判断方法：图形有透视、斜面、厚度、上下悬浮关系的，是 2.5D；只有平面的框和线的，是 2D。
- 2D 图里唯一允许的“重”元素是 `solid` 色调的核心节点（主色实心底），一张图最多两个。
- 这两套画法只约束示意图。页面框架（标题、页眉索引、结论条）和普通内容卡片仍按第 8 节。
- 组件已按此实现：色调取值在 `theme.py` 的 `tone()`（2D）与 `iso()`（2.5D），不要在页面代码里另配颜色或另加效果。

### 10.4 真实图片是证据

- 结果页、产品页优先放**真实的**软件截图、设备实拍、实验照片、数据图。真图的说服力远高于示意图标和装饰插画。
- 每张图片下面写一行说明：这是什么、在什么条件下得到的。
- 截图要裁到只剩需要看的部分；需要读者看具体位置时用 `annotated` 加编号标注，每张不超过四处。
- 对照类页面，两张图的尺寸、视角、色标范围保持一致，中间或上方用一句话写出差别（`callout`），关键数字再配一张小表。
- 数据图保持原比例、保留坐标轴与图例（`gallery(..., cover=False)`）；照片类可以裁切铺满（`cover=True`）。
- 图像生成模型只用来做封面气氛图，**不得生成“看起来像真的”截图、实验图或数据图放进正式稿件**。组件总览里的占位图是为了演示版式，正式稿件必须换成真实素材。

## 11. 图表、图片与图标

- **图表用原生图表**（`page.chart`），在 PowerPoint 里可以直接改数据。系列颜色按 `theme.series` 的顺序取，最多 5 个系列；只有一个系列时不显示图例。
- 图表旁边必须有一句“怎么读这张图”的结论，或者页标题本身就是这张图的结论。
- 坐标轴要有名称和单位；删掉不承载信息的网格线、边框、三维效果。
- **图片**（`page.figure`）等比缩放，不拉伸；下方配图注，外来图片标注来源。截图要裁到只剩需要看的部分。
- 图标统一用线性风格、同一粗细；颜色用正文色或主色。没有合适的图标就不用，不要混搭风格。
- 第三方企业标识、产品截图涉及他人品牌时，用占位框或中性描述代替，除非得到明确许可。

## 12. 禁止事项

- 引入配色之外的颜色，或在一份稿子里混用两套配色、深浅两种底色。
- 使用第 8.1 节列出的任何一种“AI 生成感”做法。
- 使用规定之外的字体；把正文缩到图注字号以下。
- 页标题折成两行；标题写成“背景”“方法”这类话题词（见 `copywriting.md`）。
- 一页出现两张以上实心重点卡片，或三处以上内容强调。
- 文字压在图片的亮部上、压在连线上、或超出卡片边界。
- 为了填满页面而拉高卡片、放大图片、增加装饰元素。
- 把文字、表格、流程图做成图片（背景和插画除外）。
- 使用动画和页面切换效果来补救版面问题。
- 把架构、链路、机制写成大段要点而不画图；连线斜穿、压字或穿过其他框。
- 用装饰插画或生成的假图冒充真实截图、实验图和数据图。
- 在 2D 示意图上使用渐变、半透明、阴影或发光；在 2.5D 示意图上描边；在一张图里混用两套画法。

## 13. 交付前视觉自查清单

渲染成图片后逐页看，每条都要过：

- [ ] 全稿只用了一套配色、一种底色、一档密度。
- [ ] 每页的页眉、页标题、页脚位置完全一致，章节索引的高亮与当前章节相符。
- [ ] 页标题都在一行内，没有被截断。
- [ ] 没有任何文字溢出容器、互相重叠、压在线上或越过 80 的页边。
- [ ] 每页只有一个视觉重点；内容强调不超过三处。
- [ ] 没有多余的次要文字（重复信息、读图提示、装饰性标签）；有实质内容的解释都还在。
- [ ] 每个内容页都有明暗层次和撞色点，同时实心色块不超过两成（第 2.5 节）；没有“整页只有背景加文字”的页面，相邻的文字块之间有头带或卡片分隔。
- [ ] 并排的模块等宽或成简单比例，顶边底边对齐，间距一致。
- [ ] 没有被拉高的空卡片；内容区留白不少于 15%。
- [ ] 连线和箭头不穿过文字和色块。
- [ ] 图表有单位、有结论；图片没有被拉伸，有图注和来源。
- [ ] 架构、链路、机制类内容画成了图；每张图节点不超过 15 个，颜色和线型的含义全稿一致。
- [ ] 2D 示意图是纯色加描边、没有阴影和光效；2.5D 示意图有阴影和柔光、没有描边；没有混用。
- [ ] 截图、照片、数据图都是真实素材，每张有说明；需要看具体位置的截图加了编号标注。
- [ ] 最小字号不低于该档的图注字号。
- [ ] 没有发光、渐变文字、背景图、标题竖条等第 8.1 节列出的做法。
- [ ] 在 PowerPoint 或 WPS 里打开核对过：字体正确、颜色与阴影正常、没有错位。（`render_pptx.py` 用的是 LibreOffice，只能发现版面问题，字间距和发光效果与 PowerPoint 有出入。）

## 14. 这些规则从哪里来

规则来自公开的设计与排版方法、通用演示实践和本项目自己的迭代，不包含任何原始汇报稿内容。

- **页眉章节索引、结论式标题、统一页脚**：让全稿读起来“成体系”，读者在任何一页都知道自己在哪、这一页在论证什么。
- **箭头步骤卡、分列清单、梯形层叠、圆形节点、托线要点块**：信息量大却不乱，靠的是严格的行列对齐和固定的颜色分工。
- **浅色底的白卡片、细边框、表头实心条、高亮结论行**：在浅色底上把层级拉开，同时保持正文可读。
- **图示与实证**（第 10 节）：分层全景、平台体系、2.5D 层叠负责给结构；运行链路、闭环图负责讲机制；分阶段路线图、分类树、图文数据页负责讲过程；中心辐射与截图对照负责用真实素材作证据。共同点是先给结构、再给细节。
- **反面教训**：每页换一种配色或版式、截图直接铺满、标题只写话题词、多种字体混用、卡片内文字溢出。禁止事项一节逐条对应这些问题。
- **配色**：基准色取自 Paul Tol 与 Okabe-Ito 的公开色卡，其余颜色在 OKLCH 空间按固定规则派生；并对照设计社区总结的 AI 默认套路逐条避开（第 8.1 节）。
- **方法依据**：Gregor Aisch 关于感知均匀色彩空间的文章、Lea Verou 与 Evil Martians 关于 LCH / OKLCH 的文章、Paul Tol 的配色技术说明、Okabe 与 Ito 的色觉通用设计、Datawrapper 的图表配色指南、Radix Colors 的色阶设计说明。
